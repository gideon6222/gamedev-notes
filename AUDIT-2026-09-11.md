# Framework audit, 2026-09-11

A full read of `INDEX.md`, the eight topic files, all nine skills, the three agents, the
setup and scripts, all seven game repos, the 44-file inbox and all eight playtest logs.
Every finding below was verified by running the command or reading the line. File and line
references are given so a session can go straight to the fix.

## Verdict

The blueprint is sound. The process table, the twelve standing rules, the sim/presentation
wall and the skill split all describe a real and working way to build these games, and the
games prove it: 1,246 typed function declarations across six repos with no untyped one, no
unseeded randomness in any `src/sim`, no Node or Viewport reference in any `src/sim`, and a
golden, smoke and tuning suite in every single repo including the oldest.

What has broken is not the plan. It is the plan's feedback loop and the way the plan
reaches a running session. Three things are wrong at the system level.

**One.** The write path of the knowledge base is wide open and the read path is frozen.
`/record-lesson` is working beautifully. `/digest` has not run since 2026-09-10 20:21.

**Two.** Most rules are written as advice about a convention rather than as a test that
fails, so a session that has not read the line repeats the bug. Six of the eight
repeat-offender classes have a concrete failing test sitting in the inbox and in no topic
file.

**Three.** The template is copied once at scaffold time and nothing ever propagates
backward, so a fix made in the template on Tuesday never reaches the game scaffolded on
Monday, and there is no way to tell which repos are behind.

Everything else in this document is a consequence of one of those three.

## 1. The digest has stopped, and that is the single largest problem

Three digest commits exist, all on 2026-09-10, the last at `1443148` 20:21:19.
`git log --diff-filter=A --name-only 1443148..HEAD -- inbox/` returns 42 files added and
zero removed. The inbox now holds 44 lessons spanning 2026-09-10 21:05 to now. Every topic
file has `1443148` or earlier as its newest commit.

Both documented triggers fired and neither produced a digest. The ten-file threshold was
crossed at 23:16 on 2026-09-10 and thirty more lessons were written after it. Wildform was
started as a new game with twelve lessons already waiting.

The consequences are measurable, not theoretical.

Four live contradictions are standing right now, where a wrong rule and its correction both
exist in the base. `techniques/generated-audio.md:212` says a node added during
`SceneTree._initialize` reports `is_inside_tree()` as **true** and the flag must not be
trusted. The undigested wildform lesson `get-tree-errors-rather-than-returning-null` says it
is **not** inside the tree until the first processed frame and makes that flag the
prescribed guard. A session reading the technique file will not write the guard the lesson
says is mandatory. `GODOT.md:169-171` says to assert the property rather than the position,
and the undigested `wildform-the-safe-area-is-not-in-window-coordinates` shows a smoke test
that asserted exactly the right property and passed for the entire time the window was
broken, because a headless run reports a safe area of zeros. Two wildform lessons on mesh
AABBs correct each other, so folding either alone writes a false rule. And one lesson's
"Replaces" field points at a line in `ASSETS.md` that does not exist, because the phrase it
quotes lives in another undigested inbox file.

Eight duplicate groups exist in the inbox, where two sessions learned the same thing
separately. The largest is nine files on "a test that passes with the feature deleted".
Five files independently redo the portrait-phone projection arithmetic that
`techniques/coreward-shop-room-and-hud.md` already contains.

Ten lessons restate something a topic file already says, which means the doc's wording did
not reach the session. Two of them say so outright. `stillwater-a-parse-error-in-a-loaded-scene-is-a-hang`
admits "the repo's own `check.ps1` prints 'a parse error is at the TOP, not the end' for
exactly this reason and I grepped past it anyway". `stillwater-screenshot-at-the-device-aspect`
admits "The repo's own `shot.gd` header said to pass `--resolution 460x996`. I had not read it."

Lessons are now being built on other lessons. `wildform-a-thing-can-only-be-destroyed-once`
cites an undigested inbox file as its authority, and `inbox/README.md` states that nothing
in the inbox is read by a build session. That chain of reasoning will never reach anyone.

**Fix.** Run `/digest` before anything else in this document. Then make the trigger real
rather than prose. The SessionStart hook already counts the inbox, so have it fail loudly
rather than print a line, or add the count to `check.ps1` so a build cannot commit with a
backlog over the threshold. The rule currently lives only as prose in
`skills/new-game/SKILL.md:19` and `skills/game-studio/SKILL.md:37` and nothing enforces it.

### The session-start hook lies about being current

`setup/settings.merge.json`, the SessionStart hook, is:

```
git -C "$n" pull --ff-only -q 2>/dev/null || echo 'gamedev-notes: pull failed ...'; c=$(...); echo "gamedev-notes: up to date (...)"
```

The `||` is statement-level. The unconditional `echo "gamedev-notes: up to date"` runs
whether the pull succeeded or failed. Every session begins by asserting the shared brain is
current, which is the one thing the hook exists to tell you. Wrap it in `if ... then ... else ... fi`.

The hook object also carries `"shell": "bash"`, which is not a field in Claude Code's hook
schema, and the path is Git-Bash-only (`/c/dev/gamedev-notes`). I could not verify the
installed `~/.claude/settings.json` because only `C:\dev` is mounted to this session. Worth
checking that the hook is firing at all.

## 2. Blocking defects, in the order they cost the most

### 2.1 `shot.gd` has photographed the wrong state in five repos since it was written

`godot-template/scripts/shot.gd:36-37`, identical in candle-gift, gravewell, wildform and
wrecking-crew:

```gdscript
for a in OS.get_cmdline_user_args():
	_seconds = float(a)
```

Every user argument is assigned to `_seconds`. The documented form is
`--script res://scripts/shot.gd -- 45 <state>` in `GODOT.md:88`,
`skills/ship/SKILL.md:35` and `setup/game-stubs/godot-CLAUDE.md:29`. `float("shop")` is
`0.0`, so the two-argument form captures the game at t=0, the title frame, and exits 0 with
a plausible-looking PNG. This is the exact failure `INDEX.md` rule 6 warns about, running
inside the tool meant to prevent it. Only `stillwater/scripts/shot.gd:57-63` parses the
second argument. Copy stillwater's parser into the template and the four repos.

`shot.gd` also writes to `user://shot.png`, outside the repo, and no topic file says where
the file lands, while `/ship` step 3 tells the session to attach it.

### 2.2 Stillwater's gate has been blind to every Godot error since it was scaffolded

`stillwater/scripts/check.ps1:29` is the pre-fix form `try { & $godot @a *> $log }` and
line 31 greps that log with `Select-String -Pattern '^(SCRIPT )?ERROR'`. The template fixed
this on 2026-09-10 in commit `73695d8` and documents why at
`godot-template/scripts/check.ps1:29-45`: `*>` renders each line as
`Godot_v4.7.2-stable_win64_console.exe : SCRIPT ERROR: ...` in UTF-16, so the anchored
pattern matched nothing, ever, and the gate reported `errors 0` on a smoke run that was
throwing inside a check and skipping every assertion after it.

Gravewell and wildform got the fix. Stillwater did not, and it is the most active repo in
the studio at 75 commits. Everything stillwater has passed locally since 2026-09-08 was
passed by a gate that could not see an error.

The same unfixed capture is still in `godot-template/scripts/movie.ps1:86`, which is the
log `skills/playtest/SKILL.md:29` tells the session to read. `TESTING.md:222-226` already
records that this fix "is still owed to `movie.ps1` and `device.ps1`" and warns that a note
of that shape is a bug report filed against yourself. It is still owed.

### 2.4 `kb.ps1 commit` commits the whole index, which is the thing it exists to prevent

`scripts/kb.ps1:45-52`:

```powershell
git add -- $Files
git diff --cached --quiet
if ($LASTEXITCODE -eq 0) { ... break }
git commit -q -m $Message -m "Co-Authored-By: ..."
```

`git commit` is called with no pathspec, so it commits everything staged, not just
`$Files`. Concurrent sessions in this worktree are the documented normal case
(`CLAUDE.md:6`, `INDEX.md:80`), so another session's staged work rides along. The
`git diff --cached --quiet` probe has the same bug in reverse and passes on someone else's
staged change. Fix both with `-- $Files`.

The blanket-add guard at line 40 is also narrower than `INDEX.md:94` claims. It rejects
only the three literals `-A`, `.` and `*`. `inbox/*` passes the filter and `Test-Path`
returns true for it, so `kb.ps1 commit -Files inbox/*` stages every unfolded lesson
including other sessions'.

present. The JDK path is pinned to `jdk-17.0.20.1+1`, which a point upgrade breaks silently.

## 3. Contradictions between documents

These are cases where two files in the base tell a session to do different things. Each one
is a coin flip at build time.

**The phone gate.** `POLISH.md:89-90` requires the full launch-to-quit pass exercised on the
phone before shipping, and `POLISH.md:84` requires perf percentiles at start and after ten
minutes. Both sit under "Performance and stability", which `skills/ship/SKILL.md:13-14` says
may **not** be deferred. But `skills/playtest/SKILL.md:39-40` says if `adb devices` shows
nothing, ship on the desk evidence and do not wait. A session with an unplugged phone has an
unresolvable gate and will resolve it by ignoring one of the two documents. Put the carve-out
in POLISH itself.

**When to stop tuning.** `INDEX.md:50` rule 8, `skills/game-studio/SKILL.md:80` and
`skills/playtest/SKILL.md:34` all say stop after **a correct fix**. `CRAFT.md:423-424` says
"When a symptom survives **two fixes**, stop fixing and measure". CRAFT is the file read
during the polish pass, and it licenses exactly the extra round of tuning rule 8 exists to
prevent.

**Font count.** `POLISH.md:38` passes a build with one self-hosted family.
`skills/asset-hunt/SKILL.md:35` requires one display family and one text family. The gate is
the thing that decides, so the gate is wrong.

**Store screenshots.** `PLAY.md:184` says aspect no wider than 2:1. `PLAY.md:188-189` says
the S26 Ultra's native resolution is already valid. `INDEX.md:4` gives that as 1080x2340,
which is 2.167:1. `skills/ship/SKILL.md:54` then instructs four screenshots at 1080x2340.
The store step produces assets the same file says Play will reject.

**Disk I/O in `src/sim`.** `INDEX.md` rule 2 names Node, Viewport, input event and real
frame, and is silent on the filesystem. The repos split two to one. `gravewell/src/sim/save.gd:6-9`
uses `FileAccess` and states "it is the same place save.gd sits in the sibling Godot games".
That is false. `stillwater/src/sim/save.gd:6` says "No FileAccess in here and no nodes" and
moves the writes to `main.gd`. Candle-gift sides with gravewell. Coreward's
`test/sim-boundary.test.mjs` header also asserts the gravewell reading. Three files now
propagate a claim about a convention that does not exist. Rule 2 needs one sentence settling
this either way.

**Menus template.** `POLISH.md:58` and `skills/game-plan/SKILL.md:74` name "Maaack's Menus
Template". `skills/game-scaffold/SKILL.md:45` installs `Maaack/Godot-Game-Template`. These
are two different asset-library entries.

**Replay flag.** `TESTING.md:191` documents `--replay=<file>`. `GODOT.md:230` says Godot eats
a leading `--` even after the separator, so a user flag is a bare word, and
`godot-template/scripts/replay_player.gd:32-41` matches only the bare `replay=`. A session
following TESTING.md verbatim gets a run with no events fed, no error, and a filmed sheet of
the idle game, which is the exact failure `TESTING.md:118-123` already describes.

**Reuse of the Playwright server.** `WEB.md:47` says `reuseExistingServer` stays `false`.
`coreward/playwright.config.ts:68` is `!process.env.CI`, and its own comment argues the
reversal is now correct because the port is per-game. WEB.md claims to be verified on
Coreward.

**Hand-list runners.** `TESTING.md:151` says any list of things to run maintained by hand
fails silently and to point runners at a glob. `godot-template/test/run_tests.gd:14-19` is a
hand-written four-element array. Candle-gift and gravewell each independently rewrote it to
a glob, and candle-gift's comment records the cost: nine tests were added, the list was not,
and the runner reported "65 passing" for a suite that was never run. Every game scaffolded
today starts with the defect the rule exists to prevent.

## 4. Rules that exist, are correct, and do not work

This is the pattern worth the most attention. In each case the rule was written down before
the bug, and the bug happened anyway, because the rule is prose in a file nobody opened at
the right moment.

**Shipped with inverted controls: five games.** Captain Run, Coreward (reported twice),
Wrecking Crew, Stillwater and Wildform. The rule is in `CRAFT.md:183-185`, `CRAFT.md:257-258`
and `POLISH.md:29`. The wildform lesson's own diagnosis is the finding: "`CRAFT.md` had the
rule and `PLAYER.md` had the precedent, and neither prevented it, because the rule was
written as advice about a convention rather than as a test that fails." The test that catches
it, driving a real `InputEventScreenDrag` through the handler and asserting
`main._cam.transform.basis.x.x > 0.5`, which reported -1.00 before the fix, exists only in
the inbox.

**A check that passes because nothing happened.** `INDEX.md` rule 11 and `TESTING.md:139`
both state it. A coreward lesson from 2026-09-10 noted it was already the third time in one
project. Nine more inbox lessons from the following eighteen hours are the same fault.

**The positive control before writing down a miss.** In `TESTING.md:82` and `ASSETS.md:103`,
two files. The asset scout still wrote down "KayKit has zero creature repos" off a 404.

**The safe-area inset.** `GODOT.md:156-165` carries the Gravewell instance with a measured
number (104 px) and the fix (guard behind `OS.has_feature("mobile")`, convert through
`window_get_size()`). Wildform used `window_get_size()` as instructed and skipped the mobile
guard, `get_display_safe_area()` returned the desktop rect, the inset became an outset of
-1460, and the branch pips that the whole evolution mechanic is steered by were absent from
the screenshot.

**"Is this cell open" after the player is inside material.** Three instances in gravewell
alone, named as such in `inbox/2026-09-11-gravewell-a-pressure-the-player-causes.md:24`. The
rule is in no topic file at all.

**A quantity computed twice.** `INDEX.md` rule 10 states it generically. Three instances in
gravewell, a fourth in coreward.

**The instrument is the thing that is wrong.** `playtests/stillwater.md:145` records "the
fourth time in six sessions he has named a fault a screenshot had already had the chance to
show me". Four more instances sit in the current inbox. No topic file names this class.

The shared fix is mechanical, not editorial. Every one of these classes has a test that
would fail. Put those tests in `godot-template/test/` so a scaffolded game inherits them,
rather than putting the sentence in a file and hoping. Specifically worth promoting today:
the handedness test, `test_version.gd` with `version/code` included, the glob runner with an
empty-glob failure, a mechanical `src/sim` boundary test in the style of Coreward's
`sim-boundary.test.mjs`, and an assertion-count floor.
