# Give the test harness a `Logger` (`OS.add_logger`) that counts engine errors per test and fails the test whose body raised one with the error's own text, because a floor on the assertion count only says something bailed, and assert every precondition a test's assertions sit behind, because an `if` that is never true is a body that never ran.

**Game:** stillwater  **Date:** 2026-09-12  **Belongs in:** TESTING.md / the section about the harness lying / an aborted test body reported as passing

## What happened
On 2026-09-11 a Stillwater test called a method that did not exist; GDScript threw, the body aborted at that line, the runner printed "107 tests, all passing", and reintroducing the bug the test was written for STILL passed because the only assertion that could catch it was after the throw. The floor on the assertion count (MIN_ASSERTIONS) and the template's "a test that asserts nothing fails" rule are canaries: they say something bailed, not what. Godot 4.5+ has a scriptable `Logger` (`class _Errors extends Logger`, override `_log_error(function, file, line, code, rationale, editor_notify, error_type, backtraces)`, install with `OS.add_logger(logger)`, remove with `OS.remove_logger`). Verified on 4.7.2 with a probe: a script error inside a called function and a `push_error` both arrive (`error_type != Logger.ERROR_TYPE_WARNING`), warnings can be filtered out, and the error's `code`, `file`, `line` and `function` are all there. The template's `test/harness.gd` now installs one in `_init`, `begin()` closes the previous test and a new `end()` closes the last (run_all calls it; run_smoke's `_finish` calls it), and a test with errors during its body is failed with the first error's own text and line. Reintroduced the bug: the runner now prints `FAIL test_zz > ...: the body raised 1 engine error, and nothing after the first one ran: Invalid call. Nonexistent function 'no_such_method' ... (test_zz.gd:6 in test_...)`. Two traps met on the way: (1) a probe that raises the error in `_init` itself kills the probe - the abort skips the print and the `quit()`, and a `--script` run with no quit HANGS rather than failing, so raise the error in a helper function called from `_init`; (2) the asserted-nothing rule, once ported, found a real vacuous test on its first run: `test_an_offering_is_never_a_trade` hooked at 150 m, where no offering row reaches, so its assertions sat inside an `if` that was never true and it had passed since the day it was written. Precondition inside an `if` is the same fault as the abort: green because nothing happened.

## The rule
Give the test harness a `Logger` (`OS.add_logger`) that counts engine errors per test and fails the test whose body raised one with the error's own text, because a floor on the assertion count only says something bailed, and assert every precondition a test's assertions sit behind, because an `if` that is never true is a body that never ran.

## Replaces or contradicts
`const MIN_ASSERTIONS` is a canary, not a target. Grep for `SCRIPT ERROR` too.
